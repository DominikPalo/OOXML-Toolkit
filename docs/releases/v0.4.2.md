Maintenance release: the app now runs on **Electron 45**, **EMF / WMF previews are more faithful**, and the project has contributing guidelines and a security policy.

## Changed

- **Electron 45.** The app is built on Electron 45 (Chromium 156, Node 24.22), up from Electron 44, and
  picks up the security fixes of the newer Chromium.
- **EMF / WMF previews.** Metafiles are converted with emf-converter 4.24.0 (up from 4.11.3), which
  places text, draws gradients and decodes CMYK images closer to how Windows renders them.
- **Dependencies.** CodeMirror, React, electron-builder and the build tooling (Vite 8, electron-vite 6)
  are up to date.

## Project

- **Contributing.** The repository now has a [code of conduct](https://github.com/DominikPalo/OOXML-Toolkit/blob/main/CODE_OF_CONDUCT.md),
  [contributing guidelines](https://github.com/DominikPalo/OOXML-Toolkit/blob/main/CONTRIBUTING.md),
  a [security policy](https://github.com/DominikPalo/OOXML-Toolkit/blob/main/SECURITY.md) for reporting
  vulnerabilities privately, and issue forms for bug reports and feature requests.
- **Supply chain.** Dependabot keeps dependencies and GitHub Actions current, pull requests get a
  dependency review, every workflow action is pinned to a commit, and the repository is checked by the
  OpenSSF Scorecard.

### First launch — the builds are not notarized yet

- **macOS:** drag the app from the `.dmg` to *Applications* and open it once — macOS blocks it. Then open
  **System Settings → Privacy & Security**, scroll down and click **Open Anyway** next to
  “OOXML Toolkit was blocked”. (macOS 14 and earlier: right-click the app → **Open** instead.)
  From a terminal, this does the same: `xattr -dr com.apple.quarantine "/Applications/OOXML Toolkit.app"`.
  Notarization needs a paid Apple Developer ID; until then this one-time step is required.
- **Windows:** SmartScreen may warn about an unrecognised app — choose **More info → Run anyway**.
- **Linux:** `chmod +x OOXML-Toolkit-0.4.2-linux-x86_64.AppImage && ./OOXML-Toolkit-0.4.2-linux-x86_64.AppImage`.
  If it does not start, install FUSE 2 (`libfuse2` / `fuse2`).

## About OOXML Toolkit

View, edit and compare Office Open XML packages (`.docx`, `.xlsx`, `.pptx` and friends) and OpenDocument packages right down to the XML: a tree of every part and element, source editor and inspector, worksheet / document / slide previews, text / regex / XPath search, side-by-side comparison, bookmarks and history, and a package check. Everything in [0.4.1](https://github.com/DominikPalo/OOXML-Toolkit/releases/tag/v0.4.1) is included — see the [README](https://github.com/DominikPalo/OOXML-Toolkit#readme) and the [user guide](https://github.com/DominikPalo/OOXML-Toolkit/blob/main/docs/guide.md).

![Animated tour](https://raw.githubusercontent.com/DominikPalo/OOXML-Toolkit/main/docs/demo.gif)

## Known limitations

- Password-protected Office files and legacy binary formats (`.doc`, `.xls`, `.ppt`) cannot be opened.
- OpenDocument files have no slide, document or worksheet preview yet.
- The package check verifies structure, not ECMA-376 schema validity.
- The slide and worksheet previews are simplified (no fonts/fills/charts; raw cell values).
- Builds are not notarized (see above) and there is no auto-update yet.
